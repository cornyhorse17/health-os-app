# Health OS App — спецификация (SPEC.md)

Версия спецификации: 1.0 (2026-11-09). Код v1.0.0 написан по этой спецификации (Claude); дальнейшее сопровождение и доработки — Perplexity Computer. Этот файл — единственный источник требований к приложению. Любой сеанс доработки начинается с чтения SPEC.md, BACKLOG.md и CHANGELOG.md, а не с истории чатов.

## 1. Что это
Личная рабочая среда здоровья для одного пользователя (Ваня, iPhone). Веб-приложение (PWA), устанавливается на главный экран iPhone. Профессиональный уровень: продуманный интерфейс, быстрый ввод, наглядная картина, работа офлайн.
Центр системы — пользователь: его чек-ины, план дня, протокол, эксперименты, анализы, питание. Garmin — один из необязательных источников: все блоки Garmin скрываются, если данных нет; приложение полностью работает без них.
Анализ и рекомендации делает Perplexity (проект Health OS: задачи по расписанию и Search-чаты). Приложение — интерфейс ввода и отображения; своей «умной» логики на сервере у него нет.

## 2. Архитектура (не менять без явного решения пользователя)
- Код: публичный репозиторий `cornyhorse17/health-os-app`, GitHub Pages (ветка main, корень). В коде НЕТ медицинских данных, токенов, имён препаратов в примерах.
- Данные: приватный репозиторий `cornyhorse17/health-os-data`, папка `data/` (+ существующие `project_files/*.md`, `garmin/`).
- Доступ: GitHub fine-grained token (только health-os-data, Contents: Read and write). Вводится один раз на экране настройки, хранится в localStorage телефона. Никогда не логируется и не коммитится.
- Стек — без сборки, чтобы доработки были дешёвыми и надёжными: HTML + ES-модули, Preact + htm (+ @preact/signals), uPlot для графиков, marked для Markdown. Все библиотеки — локальные копии в `/vendor` с закреплёнными версиями (никаких CDN во время работы). Никаких npm, бандлеров, TypeScript-сборки.
- PWA: manifest (иконка, standalone, тёмная тема), service worker: кэш оболочки, офлайн-режим, очередь записей (запись сохраняется локально и отправляется в GitHub при появлении сети).
- Запись в GitHub: Contents API (GET → sha → PUT). При конфликте (409/422) — перечитать файл, слить изменения по полям, повторить. Один файл на день для чек-инов и еды — конфликтов почти нет.

## 3. Модель данных (`health-os-data/data/`)
JSON — источник правды для структурированных данных. Markdown в `project_files/` остаётся для повествования (STATE, PROFILE, DECISIONS, KNOWLEDGE, DAILY_LOG).

- `checkins/ГГГГ-ММ-ДД.json`
```json
{"date":"2026-11-10",
 "morning":{"time":"07:55","energy":7,"mood":6,"sleep_feel":5,"voice":8,"weight_kg":78.6,"note":""},
 "evening":{"time":"22:10","energy_day":5,"focus":6,"mood":6,"voice":4,"stress":5,"appetite":3,"gi":2,"caffeine":["08:00","13:30"],"note":""},
 "adherence":{"<protocol_id>":"22:05"},
 "training":[{"type":"strength","duration_min":60,"rpe":8,"note":"","sets":[{"ex":"Жим лёжа","kg":60,"reps":8,"sets":3}]}],
 "updated_at":"2026-11-10T22:11:00+05:00"}
```
Шкалы 0–10. appetite: 0 нет аппетита … 10 сильный голод. gi: 0 нет симптомов … 10 сильные (тошнота/ЖКТ).
- `meals/ГГГГ-ММ-ДД.json` — `{"date":..., "items":[{"time":"13:10","desc":"плов с говядиной","kcal":650,"protein_g":32,"fat_g":24,"carbs_g":75,"confidence":"low|medium|high","advice":"...","source":"api|search|manual"}], "totals":{"kcal":..,"protein_g":..,"fat_g":..,"carbs_g":..}}`. Фото по умолчанию не хранится (настройка).
- `protocol.json` — `{"updated":..., "active":[{"id":"astaxanthin","name":"Астаксантин","kind":"supplement|peptide|drug|injection","dose":"4 мг","times":["21:00"],"days":"daily","since":null,"purpose":"","review":null,"schedule":{"every_days":7,"time":"22:00"}}], "candidates":[{"id":"creatine","name":"Креатин","verdict":"","evidence":"A","next_step":""}], "stopped":[{"id":..,"name":..,"date":..,"reason":..}]}`
- `injections.json` — `[{"at":"2026-11-07T22:00+05:00","drug_id":"retatrutide","dose_mg":2,"site":"живот слева","note":""}]`
- `training.json` — `{"plan":[{"weekday":1,"type":"strength","focus":"верх"}], "working_weights":{"Жим лёжа":{"kg":60,"reps":8,"date":"2026-11-10"}}, "pool":{"per_week":2}}`
- `labs.json` — `{"results":[{"date":"2026-05-15","marker":"Ферритин","value":45,"unit":"нг/мл","ref_low":30,"ref_high":400}], "plan":[{"name":"Стартовая панель","due":"2026-11-20","items":["ОАК","Ферритин"],"status":"planned|done"}]}`
- `experiments.json` — `{"active":[{"id":"E-001","title":"","start":"2026-11-08","days":7,"metric":"evening.voice","success":"","stop":""}], "queue":[...], "closed":[{"id":..,"verdict":"works|no|unclear","summary":".."}]}`
- `alerts.json` — `[{"date":"2026-11-10","level":"info|warn|critical","text":"","until":"2026-11-12"}]`
- `briefings/ГГГГ-ММ-ДД.md` (утро) и `briefings/ГГГГ-ММ-ДД-evening.md` (вечер) — пишут задачи Perplexity.
- `reviews/ГГГГ-Www.md` — недельные обзоры.
- `feedback.json` — пожелания к приложению из кнопки «Улучшить» `[{"date":..,"text":..,"status":"new|planned|done"}]`.
- Garmin (необязательно): `garmin/daily.json` — `[{"date":..,"sleep_h":..,"hrv":..,"rhr":..,"bb_wake":..,"stress":..,"steps":..}]`. Если файла нет или он пуст — блоки Garmin не показываются.

Все JSON — UTF-8, отступ 1 пробел, даты ISO, время Asia/Qyzylorda (UTC+5). Неизвестные поля сохранять при перезаписи (не терять то, что добавили задачи).

## 4. Экраны (нижняя панель вкладок, 5 вкладок)
1. **Сегодня**
   - Шапка: дата, статус дня (чек-ин утро/вечер: сделан/нет).
   - Карточка брифинга (из briefings/сегодня.md, свёрнута до 4 строк, раскрывается). Нет брифинга — неброская заглушка.
   - Предупреждения из alerts.json (цвет по level).
   - **План дня**: приёмы из protocol.json по времени с галочками (галочка = отметка времени в adherence), запланированная тренировка, таймер до следующей инъекции.
   - Активный эксперимент: «день 4 из 7», мини-график метрики.
   - Быстрые действия: Чек-ин · Еда · Тренировка · Заметка.
   - Блок Garmin (только если есть данные): сон, HRV, пульс покоя, Body Battery относительно 14-дневной медианы.
2. **Чек-ин** (центральная кнопка «+»): переключатель Утро/Вечер (по времени суток по умолчанию). Крупные ползунки 0–10 с подписями, поля веса и кофе, заметка (диктовка клавиатуры iOS). Предзаполнение вчерашними значениями приглушённым цветом. Сохранение одной кнопкой, вибро-подтверждение (если доступно) и тост «Сохранено». Цель — чек-ин за 30 секунд.
3. **Тренды**: период 14/30/90 дней. Графики: энергия утром + сон-ощущение; настроение/фокус/стресс; голос; вес; аппетит/ЖКТ; соблюдение протокола (%); калории и белок; Garmin-графики — если есть данные. Наложение событий (старт/стоп средства, инъекции) вертикальными метками.
4. **План**: подвкладки — Протокол (активные, кандидаты с вердиктами, отменённые), Инъекции (следующая, история, ротация мест), Тренировки (план недели, рабочие веса, журнал), Анализы (таблица с отметками вне референса, график по маркеру, план пересдачи), Эксперименты (активные, очередь, закрытые).
5. **Ещё**: Обзоры (рендер markdown недель), Питание (журнал по дням, итоги КБЖУ), Настройки, «Улучшить приложение».

## 5. Ввод еды
- Кнопка «Еда» → фото (камера iPhone) или описание текстом → результат: блюдо, ккал, Б/Ж/У, уверенность, совет под мои цели (рекомпозиция, белок на ретатрутиде) → подтвердить/поправить → запись в meals/.
- Режим A (в v1.0 НЕ реализован — см. BACKLOG; если в настройках введён ключ Perplexity API): запрос к Perplexity API с моделью, поддерживающей изображения; строгий JSON-ответ. Фото сжимается на устройстве до ≤1024 px. Перед реализацией проверить, что API принимает запросы из браузера (CORS); если нет — режим A не делать, отметить в BACKLOG.
- Режим B (по умолчанию, бесплатно): приложение копирует готовый промпт в буфер и открывает приложение Perplexity; пользователь вставляет фото в Search-чат проекта; Search оценивает КБЖУ и пишет запись в meals/ через GitHub (так прописано в инструкции проекта). Приложение показывает записи после обновления.
- Ручной ввод — всегда доступен.

## 6. Напоминания и таймеры
- В приложении: обратный отсчёт до инъекции, приёмов, тренировки, пересдачи анализов.
- Push-уведомления без сервера невозможны, поэтому: кнопка «Экспорт в Календарь» генерирует на устройстве .ics (повторяющиеся события с напоминаниями: инъекция по расписанию, приёмы по времени, тренировки по плану, даты анализов) → импорт в Календарь iPhone. После изменения протокола приложение показывает «Обновить календарь».
- Брифинги, напоминание о чек-ине, недельный обзор и предупреждения присылают задачи Perplexity (уведомления приложения Perplexity).

## 7. Дизайн
- Ощущение нативного iOS: системный шрифт (-apple-system), крупные заголовки, карточки со скруглением 16, мягкие тени не использовать, тёмная тема по умолчанию + светлая по системной настройке, safe-area отступы, жесты (свайп между Утро/Вечер, pull-to-refresh).
- Цвет как смысл: один акцент; зелёный/жёлтый/красный — только для статусов и отклонений.
- Скелетоны при загрузке, пустые состояния с подсказкой, понятные ошибки («Нет сети — запись сохранена и уйдёт позже»).
- Язык интерфейса — русский. Доступность: контраст AA, размер касаний ≥44 px.
- Без медицинских дисклеймеров в интерфейсе.

## 8. Безопасность
- Токен и ключ API только в localStorage, поле ввода типа password, кнопка «Удалить с устройства».
- Необязательный PIN (4–6 цифр) на открытие приложения (защита от случайного просмотра).
- CSP-заголовок через meta: только свой origin + api.github.com (+ API Perplexity, если включён режим A).
- Никакой аналитики и сторонних запросов.

## 9. Качество и сопровождение
- Структура: `index.html`, `app/` (модули по экранам), `lib/` (github.js, store.js, ics.js, charts.js), `vendor/`, `sw.js`, `manifest.webmanifest`, `SPEC.md`, `BACKLOG.md`, `CHANGELOG.md`, `README.md`.
- Версия приложения (semver) показывается в Настройках; каждое изменение — запись в CHANGELOG.md.
- Тестовые данные: `demo/` с вымышленными данными и режим «Демо» (без токена) — чтобы проверять интерфейс без доступа к личным данным.
- Проверка после каждой фазы: открыть Pages-URL, пройти чек-лист фазы, проверить консоль на ошибки. Не более 3 попыток исправить одну проблему — затем записать в BACKLOG и сообщить.
- Доработки: пожелания копятся в feedback.json и BACKLOG.md; один сеанс доработки = один согласованный пакет пунктов; точечные правки, без переписывания и без смены стека.
